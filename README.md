# Porsche · Alpine Drive

A self-contained, browser-based mountain driving experience built around the **Porsche GLB supplied in this repository**. No substitute car, stock image, remote asset service, or backend is required.

## Run

Requires Node.js 22+ and a WebGL 2 browser. A hardware-accelerated desktop browser is recommended.

```sh
npm install
npm run dev
```

Vite serves on `0.0.0.0:5173`. Arena's `*.e2b.app` preview hosts are allowed. All browser asset URLs are same-origin.

```sh
npm run build        # Type-check and build the static production application
npm run preview      # Serve that build
```

## The experience

- **Col de Lumière:** a fictional, designed 2.8 km alpine loop, with elevation changes, a valley straight, summit bends, a viaduct, tunnel, forest, rock outcrops, signs, reflectors, and continuous guardrails.
- **Free drive** plus four complete activities: full-lap time trial, 160 km/h speed run, a technical cornering challenge, and an untimed scenic route.
- Ordered, swept-detection checkpoints; countdowns; finish screens; immediate restarts; recovery and cornering penalties.
- 120 Hz fixed-step vehicle simulation: torque/RPM response, seven-speed automatic transmission, braking/reverse, engine braking, speed-sensitive steering, friction-limited turn-in, understeer, handbrake-induced rear slip, body pitch/roll, grade forces, shoulder drag, and vehicle-footprint-aware guardrail collisions.
- Chase, lightweight cockpit, hood, and cinematic cameras. Speed-sensitive FOV, camera damping, terrain clearance, and tunnel-aware cinematic placement.
- Procedural Web Audio engine harmonics, load/RPM filtering, tire scrub, braking noise, wind, road/impact noise, and tunnel delay. Audio starts only after user interaction.
- A cinematic menu, orbitable garage, Sunset/Clear/Overcast lighting, pause/settings, restrained HUD, and live route map.
- Photo mode freezes the simulation and provides orbit, pan, zoom, FOV, framing grid, and clean PNG downloads.
- Best results, total distance, top speed, completion count, volume, quality, units, and environment are stored locally. Storage failure does not prevent driving.
- Keyboard, standard-mapped gamepad, and touch driving inputs; responsive menus and HUD.

## Controls

| Input | Action |
|---|---|
| W / ↑ | Accelerate |
| S / ↓ | Brake; reverse when stopped |
| A / D or ← / → | Steer |
| Space | Handbrake |
| R | Recover to nearest road position |
| C | Cycle camera |
| P | Enter/leave photo mode |
| Escape | Pause / close panel |

Gamepad: left stick steering, RT throttle, LT brake, A handbrake, Y camera, Start pause. Garage/photo: drag to orbit, scroll/pinch to zoom; right-drag/two-finger pan in photo mode.

## Supplied car and fidelity boundaries

The initial repository contained only `tripo_pbr_model_d95512db-562f-4ae7-9526-ad241e2fd417_meshopt-v1.glb`; there was no application to preserve.

- That original, unmodified binary now lives at **`public/assets/porsche.glb`**.
- `public/assets/porsche-driving.glb` is a meshopt-compressed, simplified derivative of the **same model and textures**, generated by `npm run optimize:model`.
- The original contains 1,976,177 triangles in one merged PBR mesh. The runtime version contains 197,613 triangles. Its proportions, orientation, original finish, and texture maps are preserved; only triangle density and runtime material response are adjusted.
- The asset has **no separate wheel meshes, steering rig, or authored interior parts**. Exterior wheels consequently remain static rather than rotating body/fender geometry. A simple additional driver-view instrument surround and animated steering wheel are used for cockpit mode; this is not a factory-authentic Porsche interior.
- Brake glow and tunnel headlight footprints are supplemental effects. The original textured lamps remain part of the supplied mesh.
- This is a tuned, lightweight driving simulation, **not** an engineering-validated tire/multibody model. Suspension is a visual body response; the car follows the road's height field. There is no vehicle damage or open-terrain off-road simulation.
- Scenery and audio are procedural. There are no licensed engine recordings, ray-traced reflections, rain, depth-of-field pass, or independently configurable paint/wheel materials. These were deliberately excluded rather than represented by nonfunctional controls.
- Porsche names and the user-supplied model are used for this project; no affiliation or asset licensing beyond the user's supply is asserted.

## Rendering and performance

Three.js / TypeScript / Vite, with no UI framework or remote runtime dependencies. ACES tone mapping, PBR textures, prefiltered studio reflections, moving directional shadows, hemispheric fill, procedural sky, distance fog, subtle pine movement, tire marks, and lightweight dust/tire haze.

Foliage is instanced in spatial batches. Rocks, grass, bollards, and posts are instanced; lane dashes are merged. Geometry is frustum culled, device pixel ratio is capped, and Balanced quality lowers resolution and shadow-map cost. Static menu shadows are cached, while driving shadows track the moving car. Photographs use the current rendering resolution. Hardware-specific frame-rate guarantees are not claimed; the visual test environment uses software WebGL.

## Architecture

| File | Responsibility |
|---|---|
| `src/main.ts` | Lifecycle, input, cameras, challenges, persistence, UI events, render loop |
| `src/route.ts` | Designed spline, arc-length sampling, nearest-road queries, terrain height |
| `src/physics.ts` | Independently testable fixed-step vehicle dynamics and collisions |
| `src/world.ts` | Road, scenery, lighting, tunnel/bridge, checkpoint geometry |
| `src/textures.ts` | Deterministic ground and pine texture generation |
| `src/car.ts` | Supplied GLB loading, material tuning, transforms, contact/light effects |
| `src/effects.ts` | Bounded, instanced tire marks and pooled dust/tire particles |
| `src/cockpit.ts` | Lightweight instrument panel and steering surround |
| `src/audio.ts` | Web Audio synthesis and spatial-condition sound response |
| `src/ui.ts`, `src/style.css` | Menu/HUD markup, activity definitions, responsive visual system |
| `scripts/optimize-model.mjs` | Reproducible optimization of the original supplied asset |

## Verification

```sh
npm test              # Route, acceleration, gears, braking, reverse, grip recovery,
                      # collisions, reset, long-run stability, time formatting
npm run build
```

With `npm run dev` running in another terminal:

```sh
npm run test:browser   # Deterministic browser integration suite
npm run test:visual    # Real WebGL screenshots and shader/console checks
```

The integration suite drives **all four activities through the real input handlers** and checks their finish targets, checkpoint order, records, restart, pause, settings, all cameras, garage, photo controls/export, reverse/recovery, reload persistence, and narrow-screen layout. GPU draw submission is suppressed in that deterministic suite, not in the application. The separate visual suite loads and renders the real GLB, captures desktop/mobile menus, driving, cockpit, and challenges, and checks for WebGL errors.

The test helper uses an npm-distributed Chromium binary on Linux, including bundled NSS dependencies for minimal hosts. Other platforms can use Playwright's installed Chromium or set `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`. Screenshots are written to ignored `.cache/screenshots/`; generated builds and test artifacts are not committed.
